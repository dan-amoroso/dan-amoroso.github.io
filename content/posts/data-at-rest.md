HTTP APIs, queues and logs, Clojure's data orientation and Erlang's actor pattern, Functional programming and even the good old Object Oriented paradigm.
These are a few of the successfull software architecture patterns that, in my opinion, share a few common features. In particular, here I want to explore what I am calling **"data at rest": they prescribe data as the interface between components.**

### why I is it effective
- data does not require a computational model to be understood
- inserting data "checkpoints" at the boundaries/interfaces in a system is the only real way to conceptually decouple regions/units of code
